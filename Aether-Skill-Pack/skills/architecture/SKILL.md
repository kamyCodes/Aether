# Architecture
Start from requirements and existing constraints.
Prefer simple boundaries and explicit data flow.
Evaluate coupling, cohesion, failure modes, observability, scalability, security, and operational cost.
Do not redesign an existing system without evidence that the current boundary is the problem.
For significant decisions, state alternatives, trade-offs, and why the chosen approach fits.
